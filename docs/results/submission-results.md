### 计算口径

1. 十六进制计数转换为整数后，逐项计算 `SoC_ratio = openla500_soc_count / mycpu_soc_count`。
2. 逐项计算 `CPU_ratio = openla500_cpu_count / mycpu_cpu_count`。
3. 对各自 20 项比值计算几何平均：`exp(sum(log(ratio)) / 20)`。
4. 功能分按 `58 / 58 * 100` 计算。

上述结果与打分表中保存的公式结果一致，两个几何平均值的差均小于 `1e-12`。表内 `H17` 的 IPC 标题与 `H21:H40` 的实际分子/分母顺序不一致，本页以实际公式和原始计数为准，统一称为 **CPU 周期比值（openla500 / myCPU）**，不将 1.1458 写成绝对 IPC。不同程序的指令数未在表中提供，因此这里也不额外推算绝对 IPC。

## 版本对应关系

对照的 GitHub 基线为默认分支 `merge-timing-ipc-up` 的提交 [`507f4af`](https://github.com/ghub1821239/NSCSCC2026-NKU-LLongarch/commit/507f4afbef3ee9dfe5c5520ff9760df48d055d8a)。最终提交包中的 `src/mycpu/` 对应本仓库 `IP/myCPU/`。

核对了 32 个 `.sv`、`.vh`、`.xci` 文件。忽略 CRLF/LF 换行格式后，30 个文件内容相同，以下 2 个文件不同：

| 文件 | 最终提交版相对 GitHub 基线的变化 |
| :--- | :--- |
| `cache.sv` | 增加独立的 load-hit way 数据选择 `rdata_hit_word`；LOOKUP 状态的数据输出减少重复 hit 门控，数据是否有效仍由响应握手约束 |
| `decode.sv` | RAS 的 `push_target` 改为依据 call 条件选择 PC+4，减少 `id_fire` 等控制进入返回地址数据选择路径 |

README 中的分数和时钟配置属于最终提交材料。GitHub 基线及文档分支未据此重新综合或上板验收，也未用 README 更新改动上述 RTL。设计文档第 9 节描述了功能测试与按槽位年龄顺序进行提交轨迹比对的方法。
