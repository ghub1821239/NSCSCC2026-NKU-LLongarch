## 3. 查看最差路径的结构特征

进入报告目录：

```tcl
cd D:/chiplab/fpga/nscscc-team/run_vivado/result/for_timing_report/
```

生成逻辑级分布报告：

```tcl
report_design_analysis \
    -timing \
    -setup \
    -max_paths 100 \
    -logic_level_distribution \
    -logic_level_dist_paths 100 \
    -show_all \
    -file design_analysis1.rpt
```

参数说明（Vivado 2023.2）：

| 参数 | 实际作用 |
| --- | --- |
| `-max_paths 100` | 只控制 **Timing Path Characteristics** 表导出多少条最差路径，默认是 1，**不会**单独决定 Logic Level Distribution 的样本量 |
| `-logic_level_distribution` | 额外生成 Logic Level Distribution 直方图 |
| `-logic_level_dist_paths 100` | 指定直方图统计用的最差路径条数；不加时默认是 **1000** |
| `-show_all` | 在 Timing Path Characteristics 表中展开更多列 |

如果意图是“对最差约 100 条路径做 Logic Level Distribution”，必须同时写 `-logic_level_dist_paths 100`。只写 `-max_paths 100` 时，明细表是 100 条，直方图仍可能按默认 1000 条统计。

合并：

```tcl
cd D:/chiplab/fpga/nscscc-team/run_vivado/result/for_timing_report/
report_design_analysis \
    -timing \
    -setup \
    -max_paths 100 \
    -logic_level_distribution \
    -logic_level_dist_paths 100 \
    -show_all \
    -file design_analysis1.rpt
```

该报告可以帮助判断最差路径主要由以下哪类因素造成：

- 组合逻辑级数过多；
- 布线距离过长；
- 扇出过大；
- 某一级流水线负载明显不均衡。

## 4. 查询指定流水线寄存器

可以使用 `get_cells` 找到实现后的触发器，并将结果保存到 Tcl 变量中：

```tcl
set IF_ID_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_decode/bus*
}]
```

命令说明：

| 参数 | 含义 |
| --- | --- |
| `set IF_ID_regs` | 将查询结果保存到 Tcl 变量 `IF_ID_regs` |
| `get_cells` | 查询设计中的实现单元，例如寄存器和 LUT |
| `-hier` | 递归搜索整个层次结构 |
| `REF_NAME =~ FD*` | 只匹配 FPGA 触发器单元 |
| `NAME =~ */u_decode/bus*` | 匹配 Decode 模块内综合后名为 `bus` 或 `bus_reg` 的寄存器 |

当前查询可以用于定位：

```text
IF_ID_bus  ->  ID 阶段  ->  ID_EXE_bus
```

分别查询前后两组流水线寄存器，再结合 `report_timing`，就可以估算 ID 阶段的逻辑和布线延迟。

```tcl
# 先查看综合后实际保留下来的流水线寄存器名称。
get_cells -hier -filter {REF_NAME =~ FD* && NAME =~ *bus_reg*}
```

在当前设计中，RTL 的总线名通常不会直接成为 cell 名。应根据上一步输出的层次名称查询，例如：

```tcl
set pre1_pre2_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_pre_IF2/bus_reg*
}]
set pre2_IF_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_fetch/bus_reg*
}]
set IF_ID_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_decode/bus*
}]
set ID_EXE1_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_exe1/bus_reg*
}]
set EXE1_EXE2_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_exe2/bus*
}]
set EXE2_MEM_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_mem/bus*
}]
set MEM_WB_regs [get_cells -hier -filter {
    REF_NAME =~ FD* && NAME =~ */u_wb/bus*
}]
```

如果某个模块的寄存器实际名称不是 `bus_reg` 或 `bus`，以 `get_cells` 输出的实际名称为准。不要直接使用 RTL 线网名（例如 `IF_ID_bus`）作为 `get_cells` 的过滤条件。

## 6. 导出所有流水级的前 60 条路径

为了避免遗漏 `EXE1 -> Icache CE` 这类不以相邻流水线总线为终点的路径，本节不限制终点，只限制每条路径的起点属于哪个流水级。

下面的过程从指定流水级所有寄存器的 `Q` 引脚出发，搜索整个设计中的所有合法时序终点，并导出最差 60 条 setup 路径：

```tcl
proc report_stage_top60 {stage_name stage_regs report_file} {
    if {[llength $stage_regs] == 0} {
        puts "WARNING: $stage_name register group is empty"
        return
    }

    set from_pins [get_pins -of_objects $stage_regs -filter {
        NAME =~ */Q
    }]

    if {[llength $from_pins] == 0} {
        puts "WARNING: $stage_name has no Q pins"
        return
    }

    puts "Reporting $stage_name -> $report_file"
    report_timing \
        -from $from_pins \
        -setup \
        -max_paths 60 \
        -nworst 1 \
        -sort_by slack \
        -path_type full \
        -input_pins \
        -file $report_file
}
```

参数说明（Vivado 2023.2，本工程日志为 v2023.2）：

| 参数 | 是否采用 | 原因 |
| --- | --- | --- |
| `-path_type full` | 采用 | Data Path 表已经包含每个 net/cell 的 `Incr(ns)`，足够拆 Route Delay |
| `-path_type full_clock_expanded` | **不采用** | 只展开时钟网络（IBUF/BUFG/PLL），不增加数据 net 的独立 delay；报告更长，还容易把时钟 net 误当成数据 net |
| `-input_pins` | 采用 | 补上 LUT 的 `I0/I1/...` 输入脚，方便对照 CELL→NET→CELL，不改变 net 的 `Incr(ns)` |
| `-sort_by slack` | 采用 | 默认本来就是 slack；写明避免以后被改成 `-sort_by group` |
| `-routable_nets` | **不采用** | 只把“经过了多少根 routable net”写成 path 对象属性，**不会**在 `.rpt` 里给出每个 net 的 delay |

旧报告如果已经是 `-path_type full`，现有 parser 可以直接拆 Data Path 表，不必为了拆 net 而重导成 `full_clock_expanded`。

在当前报告目录中，为每个流水级分别生成报告：

```tcl
report_stage_top60 \
    "preIF1" $preIF1_stage_regs \
    "01_preIF1_top60.rpt"

report_stage_top60 \
    "preIF2" $preIF2_stage_regs \
    "02_preIF2_top60.rpt"

report_stage_top60 \
    "IF" $IF_stage_regs \
    "03_IF_top60.rpt"

report_stage_top60 \
    "ID" $ID_stage_regs \
    "04_ID_top60.rpt"

report_stage_top60 \
    "EXE1" $EXE1_stage_regs \
    "05_EXE1_top60.rpt"

report_stage_top60 \
    "EXE2" $EXE2_stage_regs \
    "06_EXE2_top60.rpt"

report_stage_top60 \
    "MEM" $MEM_stage_regs \

```

执行完成后，当前目录下应生成：

```text

02_preIF2_top60.rpt

05_EXE1_top60.rpt

07_MEM_top60.rpt
```

如果某一级没有生成报告，先查看 Tcl Console 中的 `WARNING`，再检查第 5 节对应寄存器组的数量。报告中重点关注 `Data Path Delay`、`Logic Delay`、`Route Delay`、`Levels`、`Fanout`、`Slack`，以及 Data Path 表里每根 net 的 `Incr(ns)`。

## 7.2 锁定可疑 net 之后才使用 get_net_delays

不要遍历全设计调用 `get_net_delays`。只有 `timing_nets.csv` 已经指出具体 net 之后，才对那一根查询：

```tcl
set n [get_nets {SUSPECT_NET}]

set nd [get_net_delays \
    -interconnect_only \
    -of_objects $n]

foreach d $nd {
    report_property -all $d
}
```

注意单位：`get_net_delays` 对象的 delay 属性经常是 **ps**，而 `report_timing` 文本使用 **ns**。对比时必须先做 `/1000.0`，禁止和 6.81 ns 这类数值直接混比。

### 8.3 只把现有报告的第一条路径打印到 Tcl Console

下面的代码从第一次出现 `Slack (...)` 开始打印，在第二次出现 `Slack (...)` 前停止：

```tcl
set exe1_rpt {D:/chiplab/fpga/nscscc-team/run_vivado/result/for_timing_report/05_EXE1_top60.rpt}

set fp [open $exe1_rpt r]
set slack_count 0

while {[gets $fp line] >= 0} {
    if {[string match "Slack (*)*" [string trimleft $line]]} {
        incr slack_count
        if {$slack_count == 2} {
            break
        }
    }

    if {$slack_count == 1} {
        puts $line
    }
}

close $fp
```

推荐优先使用 8.1：它从当前实现设计重新取得路径，可以继续在 Vivado 中查看对应单元和布线。8.2 和 8.3 适合离线阅读已经保存的报告。

## 10. 时序路径分段与切割判据

先看这条路径依次完成了哪些功能，按功能阶段切分，不要只按 Verilog 模块名切分；每个功能阶段的输入和输出都应该有明确含义。比如当前路径可以先分成：`EXE1 操作数加法 -> TLB 地址翻译 -> valid/ready 握手控制 -> Icache 请求`，再用各分界点的累计 `Path(ns)` 相减，得到每段实际延迟。

## 9.阅读报告

| 报告中的类型 | 含义 |
|---|---|
| `FDRE` / `FDCE` | 触发器 |
| `LUT2`~`LUT6` | 查找表组合逻辑 |
| `CARRY4` | 加法器/比较器进位链 |
| `net` | 布线网络，不是逻辑单元 |
