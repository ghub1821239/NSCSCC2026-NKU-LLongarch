# 最新时序报告导出与分析

配合 `mytool/analyze_timing_full.py` 使用。目标：把最近一次实现的所有 setup path 导出成文件，自动生成“按流水级排名 + 全局最差路径 + 跨模块路径 + 高扇出网络”汇总，用于判断该拆哪一级、该压哪条长线。

## 1. 导出最新实现的所有路径

打开实现后的设计：

```tcl
open_run impl_1
```

进入报告目录（Windows 下把 `<repo>` 换成你的工程根目录）：

```tcl
cd <repo>/fpga/nscscc-team/run_vivado/result/for_timing_report/
```

### 1.1 全局汇总（WNS/TNS/Hold）

```tcl
report_timing_summary \
    -setup \
    -hold \
    -max_paths 50 \
    -file timing_summary_latest.rpt
```

### 1.2 紧凑全路径表（Path Delay / Logic / Net / Levels / High Fanout）

```tcl
report_design_analysis \
    -timing \
    -setup \
    -logic_level_distribution \
    -max_paths 1000 \
    -file design_analysis_latest.rpt
```

### 1.3 完整路径（带每级 Source/Destination 层次和 net fanout）

```tcl
report_timing \
    -setup \
    -max_paths 2000 \
    -nworst 2000 \
    -path_type full \
    -file all_paths_latest.rpt
```

如果只想看 CPU 内部，加 `-filter` 只保留 `u_cpu` 起点（可选）：

```tcl
report_timing \
    -setup \
    -max_paths 2000 \
    -nworst 2000 \
    -path_type full \
    -filter {NAME =~ *u_cpu*} \
    -file all_paths_cpu_latest.rpt
```

### 1.4 可选：按流水级导出 top60（老流程，用于严格按级分组）

沿用 `查看时序报告.md` 第 6 节的 `report_stage_top60` 过程，生成：

```text
01_preIF1_top60.rpt
02_preIF2_top60.rpt
03_IF_top60.rpt
04_ID_top60.rpt
05_EXE1_top60.rpt
06_EXE2_top60.rpt
07_MEM_top60.rpt
08_WB_top60.rpt
```

## 2. 运行分析工具

```powershell
cd <repo>/mytool
python ./analyze_timing_full.py `
    --input <repo>/fpga/nscscc-team/run_vivado/result/for_timing_report `
    --output <repo>/fpga/nscscc-team/run_vivado/result/for_timing_report `
    --cpu-only
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--input` | rpt 文件所在目录，默认就是这个报告目录 |
| `--output` | 输出目录，默认与输入相同 |
| `--top N` | 全局最差路径条数，默认 40 |
| `--cpu-only` | 只保留 CPU 层次路径，过滤 DDR3/JTAG 等系统路径，分析 CPU 时建议加 |

## 3. 看输出

### 3.1 `timing_summary.md`

按顺序看四张表：

1. **指标表**：当前时钟周期、主频、最差 Slack、WNS/TNS/Hold。
2. **按起点流水级排名**：Slack 越小越优先处理；同时看“布线占比 / Levels / 最大扇出 / 判断”。
3. **全局最差路径**：逐条看 Source → Destination，判断逻辑归属。
4. **跨模块路径**：源级 → 终级，用于找“信号从 A 级跑到 B 级”的长线。
5. **高扇出网络**：fanout ≥ 50 的控制/数据线。

### 3.2 `timing_paths.csv`

用 Excel 打开（UTF-8 BOM），按 `slack_ns` 升序、`route_percent` 降序、`fanout` 降序筛选。

## 4. 判定标准

| 现象 | 处理方向 |
| --- | --- |
| Slack < 0 | 必须处理 |
| 布线占比 ≥ 70% | 先查长线/扇出/跨模块，再考虑拆级 |
| 逻辑占比 ≥ 50% 或 Levels ≥ 20 | 组合深度问题，拆级、提前译码、拆大 mux |
| 扇出 ≥ 50 | 复制寄存器、全局控制改局部 |
| 源级/终级跨模块 | 在中间打一拍，或把该控制信号在目标模块本地寄存 |

## 5. 优化循环

```text
1. 选 Slack 最小的一条路径
2. 看 Source / Destination 属于哪一级、跨了哪些模块
3. 判断是布线长、逻辑深还是扇出大
4. 只做一个局部修改（拆一拍 / 复制信号 / 提前译码）
5. 重新综合 + 布局布线
6. 再跑本工具对比 Slack、Delay、Route%、Levels、Fanout
```

不要一次同时改流水级、ready_go、cache 接口和分支取消，否则无法判断是哪项改动生效。

## 6. 备注

- 工具只统计 `Path Type` 为 Setup 的路径，Hold / Pulse Width 自动忽略；
- `design_analysis` 表里的部分引脚没有完整层次，源级会显示 `?`，以 `all_paths_*.rpt` 和 `NN_*_top60.rpt` 的完整层次为准；
- 旧工具 `analyze_timing_reports.py` 仍可用，只处理 `NN_<stage>_top60.rpt`；新工具 `analyze_timing_full.py` 覆盖它并支持全路径/design_analysis/timing_summary。
